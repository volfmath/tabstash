# 多语言自动会话名称修复验收

日期：2026-10-01

## 问题

界面切换为英文后，之前以中文界面留空名称保存的会话仍显示为“会话 1”，而窗口数量、标签数量和时间已经显示为英文。

## 根因

留空名称会在保存时持久化为 `会话 N` 或 `Session N`。会话列表此前直接显示持久化字符串，没有按当前界面语言呈现自动生成的名称。

## 修复

- 自动生成的 `会话 N` 和 `Session N` 在当前界面中互相本地化。
- 会话列表标题、删除确认、恢复标题和保存成功提示统一使用本地化名称。
- 用户自行输入的其他名称保持原文。
- 没有标题的被排除标签由界面按当前语言显示占位文本，不再由采集层写死中文。
- 设置页反馈入口统一切换到 GitHub Issues 和 GitHub 提交记录。
- 新增回归测试覆盖中英文自动名称和用户自定义名称。

## 本轮补充审查与修复

- 检查所有用户可见提示与系统原生确认框时，补齐恢复任务异常和语言偏好写入失败的本地化，避免显示浏览器原始错误语言。
- 自动命名的保存预览标题会跟随当前界面语言；确认保存仍使用预览时语言和后台原子编号。
- 设置页显示 GitHub feedback 入口说明；坏网址的主机名回退、恢复失败项标题按界面语言呈现。
- 真实 Chromium 验收验证英文删除确认可取消且不删除、中文删除确认的完整文案及确认行为。
- 首次复核发现先前 ZIP 误含 CRXJS 开发产物；现已从生产构建 `dist` 重新打包。生产 HTML 引用打包后的静态资源，service worker 不引用 localhost，manifest 不含开发模式的 `web_accessible_resources`。
