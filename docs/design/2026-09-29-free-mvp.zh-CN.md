# Tabstash 免费版 MVP 设计草案

状态：产品基线已确认；本文的实现细节待用户审阅。本文只设计首个免费版本，不开始实现。

## 目标与边界

目标用户是经常同时打开多个项目或研究资料的 Chrome 用户。首版要让用户手动保存一个工作现场，并在以后可靠地打开它。可靠性承诺只覆盖**已明确提示保存成功**的会话；未保存标签页的崩溃恢复不属于免费版。

免费版包含：保存当前窗口或全部普通窗口、恢复到新窗口、会话列表与搜索、重命名与删除、按域名查看标签、快捷键、最多 5 个本地会话、JSON 备份与导入。Pro 在后续版本提供无限会话、自动保存、跨设备加密同步、会话模板和 Markdown 导出。首版不要求账号、服务端、支付或后台持续采集浏览状态。

“全部窗口”指当前浏览器配置文件中的普通窗口；隐身窗口、扩展弹窗及开发者工具窗口不纳入会话。保存多窗口时保留窗口之间的划分和每个窗口内的标签顺序，不承诺恢复窗口位置、尺寸、标签组、浏览历史、页面滚动位置或登录状态。

## 用户流程（原则已确认，细节待审阅）

1. 用户在扩展弹窗中输入会话名称；范围下拉菜单选择“当前窗口”或“所有窗口”。“当前窗口”为默认值。弹窗显示将保存的窗口数和可恢复标签数。
2. 后台读取标签、检查上限和可保存的网址，写入本地存储。只有写入成功才显示“已保存”。没有可恢复标签时拒绝创建空会话；部分标签无法保存时列出排除数量和原因，供用户确认后再保存。
3. 弹窗按创建时间倒序列出会话，支持按会话名、标签标题和 URL 模糊搜索。会话详情先按原窗口、再按主机名展示标签；该分组仅用于浏览，不改变原始顺序。
4. 用户可以重命名、删除会话。删除前确认；达到 5 个会话时禁止新增并提示删除旧会话或导出备份，绝不自动覆盖。
5. 恢复单窗口会话时直接创建一个新窗口。恢复多窗口会话时，先选择“保留窗口结构”或“合并为一个窗口”，然后只创建新窗口，不修改现有窗口。合并时按保存时的窗口顺序依次排列标签。
6. 恢复是非破坏性操作：原会话始终保留。若部分网址打开失败，显示失败列表；已打开的标签和窗口保留。用户再次恢复可能产生重复标签，因此失败反馈中应说明这一点。

JSON 备份与导入放在扩展设置页，避免占用高频使用的弹窗空间。弹窗提供进入设置页的入口。

快捷键触发同一个保存流程，不能绕过范围和名称确认。默认快捷键可按 README 尝试配置，但浏览器或系统可能占用；扩展始终保留弹窗入口，并允许用户在浏览器扩展快捷键设置中调整。

## 数据模型

一个存储键保存完整的版本化状态；所有数据都在 `chrome.storage.local`，不使用 `chrome.storage.sync`。建议形状如下，字段名在实现时可随项目惯例微调，但语义不变。

```typescript
interface StoredState {
  schemaVersion: 1;
  sessions: SavedSession[];
}

interface SavedSession {
  id: string;             // UUID，避免时间戳碰撞
  name: string;
  createdAt: string;      // ISO 8601
  windows: SavedWindow[]; // 数组位置代表原始窗口顺序
}

interface SavedWindow {
  tabs: SavedTab[];       // 数组位置代表原始标签顺序
}

interface SavedTab {
  url: string;
  title: string;
}
```

只持久化恢复所需的 URL、标题和顺序，不持久化网页内容、Cookie 或可能很大的 favicon data URL。界面从 URL 计算主机名。只将可正常重新打开的 `http:` / `https:` 标签纳入首版保存范围；`chrome:`、`about:`、扩展页面、`file:` 等网址在保存前列为排除项。这个边界避免“显示保存成功但网址无法恢复”。未来如果支持其他协议，需逐类定义权限、验证和迁移规则。

## 模块职责与数据流

- **弹窗 UI**：保存表单、列表、搜索、会话详情、恢复选择及结果反馈。只调用后台命令，不直接改写持久状态。
- **后台 service worker**：统一处理读取浏览器窗口、保存、重命名、删除、导入和恢复；同一时刻串行处理会话写操作。恢复任务由后台执行，弹窗关闭不主动取消。任务进度和失败项短暂写入 `chrome.storage.session`，以便重开弹窗后查看；若浏览器或 service worker 中断，重开弹窗时将停留过久的任务标为“结果未确认”，不自动续传或重试，以免打开重复标签。
- **会话存储模块**：读取并校验版本化状态；每次修改从最新状态生成候选对象，再以单个存储键写回。写入失败后重新读取现有状态并如实反馈；捕获配额与 API 错误。不把一次存储 API 成功夸大为断电级持久化保证。
- **备份模块**：导出带 `schemaVersion`、导出时间和会话数据的 JSON；导入时先完整解析、校验结构与 URL，再显示预览。首版只追加不覆盖：备份文件内部有重复 ID 则拒绝；与现有会话同 ID 的记录跳过；新增记录会使总数超过 5 个则整次导入失败，现有数据保持不变。用户可先删除旧会话再导入。

弹窗向后台发送命令，后台返回成功、可预期的业务错误或失败标签清单。存储中的 `schemaVersion` 为以后从免费版升级至 Pro 提供迁移入口，但首版不预建云同步或付费接口。

### 本地存储取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 一个版本化状态对象存入 `chrome.storage.local` | 无需维护会话索引，五个会话下读写和导入容易校验 | 修改一项也会重写状态；受本地配额限制 | 首版采用 |
| 每个会话单独存储 | 单项写入更小 | 索引和记录可能不同步，需要额外一致性处理 | 暂缓 |
| IndexedDB | 事务和大数据量更有余地 | 首版实现、迁移和调试成本更高 | 有规模证据后再考虑 |

## 失败处理与隐私

- 保存：在读取完全部目标窗口后再校验上限和数据。排除项必须在写入前明确显示；保存成功只针对实际纳入的标签。写入失败、配额不足或校验失败时不显示成功，不自动删除旧会话。
- 恢复：先验证每个保存的网址。以首个可打开的网址创建每个新窗口，再按保存顺序创建其余标签，避免遗留初始空白标签。对浏览器 API 错误逐项记录；若整个浏览器/扩展中断，原会话仍可再次尝试，但不能承诺自动续传。
- 导入：对版本、字段类型、文件内部重复 ID、网址协议及会话数量进行校验；文件不合法或超过限制时整次拒绝。JSON 明文包含可能敏感的 URL 和查询参数，导出前提示用户妥善保存备份。扩展不上传这些数据。
- 卸载扩展、清除扩展数据或损坏浏览器配置文件仍可能导致本地数据丢失；JSON 备份是用户可控的恢复途径。产品文案不得宣称“绝不丢数据”。

## 验证与发布标准

核心验证覆盖：当前窗口和全部普通窗口保存、窗口/标签顺序、空窗口与不可恢复网址、5 个会话上限、100+ 标签、并发保存/重命名、存储配额失败、恢复部分失败、JSON 导出后在全新数据环境导入、非法/重复/超额备份、弹窗关闭后恢复继续执行。兼容性先以 Chrome 当前稳定版为发布门槛，再验证 Edge 与 Brave；旧版 Chrome 的支持范围以实际 API 和测试结果决定。

发布前还需检查扩展权限最小化：读取所有窗口 URL 与标题需要适当的 `tabs` 权限，存储需要 `storage`；首版不需要主机权限、内容脚本、网络后端或长期后台轮询。隐私政策应明确说明本地保存 URL 和 JSON 明文备份行为。
